How to read this handbook

You need no prior knowledge. If you can open a terminal and type a command, you can follow along.

Read the parts in order the first time, because each one builds on the last. Every chapter follows the same seven steps, so you always know where to look.

  1. ConceptThe idea in two or three sentences
  2. AnalogyA real-life comparison
  3. DiagramWhat happens inside the repo
  4. CommandsEach command with sample output
  5. MistakesWhat goes wrong and the fix
  6. RecapA one-minute revision list
  7. ExerciseA task to try yourself

Conventions

In a dark code block, a line that starts with $ is a command you type. The $ itself is not part of the command. Lines without it are the output Git prints back. The copy button copies only the commands.

$ git status
On branch main
nothing to commit, working tree clean

Words in <angle brackets> are placeholders. In git checkout <branch-name> you type the real branch name and leave out the brackets. Tick the boxes in each exercise to track progress; the sidebar shows a check beside a finished chapter.
