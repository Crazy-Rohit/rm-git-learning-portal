Branch protection and CODEOWNERS

Protection rules make sure nothing reaches the main branch without review and passing checks, even by accident.

33.1 The problem

Rules in a document are easy to forget. Branch protection turns them into settings that GitHub enforces for everyone, including administrators if you choose.

33.2 Common rules

Open Settings, then Branches (or Rules, then Rulesets), and add a rule for main.

RuleWhat it enforces
Require a pull requestNo direct pushes to main
Require approvalsAt least one or two people must approve
Dismiss stale approvalsNew commits cancel old approvals
Require status checksChosen workflows must pass first
Require conversation resolutionAll review threads must be resolved
Require linear historyOnly squash or rebase merges are allowed
Block force pushesHistory cannot be rewritten
Block deletionsThe branch cannot be deleted
Require signed commitsCommits must carry a verified signature

33.3 Rulesets

Rulesets are the newer, more flexible way to do this. They can target several branches or tags with patterns, can apply across an organisation, and can run in an evaluate mode first, which reports what would have been blocked without enforcing anything. Use them when you have more than a couple of rules.

33.4 CODEOWNERS

A file named CODEOWNERS assigns people or teams to parts of the codebase. When a pull request touches those files, GitHub asks the owners to review.

# Everything
*                  @your-username

# Documentation
/docs/             @docs-team

# Workflows need an admin's eye
/.github/workflows/ @your-username

Place the file in .github/, the root or docs/. With the rule Require review from Code Owners, no one can merge changes to those files without an owner's approval.

33.5 A sensible starting setup

  • Require a pull request with one approval.
  • Require the CI check to pass.
  • Block force pushes and deletions.
  • Add a CODEOWNERS file for sensitive paths.

33.6 Common mistakes

  • Requiring checks that never run. The pull request will wait forever. Make sure the check name matches your workflow job.
  • Too strict for a small team. Five required reviewers slows everyone. Match the rules to your team size.
  • Letting admins bypass rules routinely. The exception becomes the habit.
Quick recap
  • Protection rules enforce reviews and checks on important branches.
  • Require pull requests, approvals, status checks and no force pushes.
  • Rulesets are the modern, flexible alternative.
  • CODEOWNERS routes reviews to the right people.
