GitHub Actions

Actions runs your tests and scripts automatically whenever something happens in your repository, and it works as the engine of your whole workflow.

31.1 What Actions does

GitHub Actions is a built-in automation service. When an event occurs, such as a push or a pull request, GitHub starts a virtual machine and runs the commands you describe. The most common use is continuous integration (CI): every change is built and tested automatically, so mistakes show up in minutes.

31.2 The vocabulary

TermMeaning
WorkflowAn automated process defined in one YAML file
EventWhat starts the workflow: a push, a pull request, a timer
JobA group of steps that run on one machine; jobs can run in parallel
StepOne command, or one reusable action
RunnerThe machine that runs the job (for example ubuntu-latest)
ActionA reusable building block written by you or others

31.3 Your first workflow

Create the file .github/workflows/ci.yml in your repository.

name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest

Reading it from top to bottom: run on every push to main and on every pull request; start an Ubuntu machine; fetch the code; install Python; install dependencies; run the tests.

Note

Action versions such as @v4 change over time. Check each action's page on the GitHub Marketplace for the newest major version before you copy a workflow.

$ git add .github/workflows/ci.yml
$ git commit -m "Add CI workflow"
$ git push

31.4 Watching it run

Open the Actions tab of your repository. Each run shows a green tick or a red cross. Click a run, then a job, to read the log of every step. On a pull request, the same result appears at the bottom as a check. A failed step stops the job. Fix the code, push again, and the workflow re-runs. You can also choose Re-run jobs on a run page.

31.5 YAML in two minutes

  • YAML uses spaces for nesting, never tabs. Two spaces is standard.
  • A line starting with - is a list item.
  • key: value pairs make a dictionary.
  • Quote values that could be misread, like "3.12", which would otherwise be read as the number 3.12.

31.6 Common mistakes

  • Wrong folder. Workflows must be in .github/workflows/.
  • Tab characters. They break YAML. Use spaces.
  • Forgetting actions/checkout. Without it, the runner has none of your files.
  • Misquoting versions. Python 3.10 unquoted becomes 3.1.
Quick recap
  • Actions runs workflows when events happen in your repository.
  • A workflow has jobs; a job has steps; steps run commands or actions.
  • Workflows live in .github/workflows/*.yml.
  • Results appear in the Actions tab and as checks on pull requests.
