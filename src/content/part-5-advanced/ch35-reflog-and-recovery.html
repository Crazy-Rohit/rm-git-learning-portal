Reflog and recovery

Git rarely loses committed work, and the reflog is the diary that lets you find it again.

35.1 The safety net

You ran git reset --hard and your commits disappeared from git log. They are not truly gone. Git keeps a private diary, the reflog, of every place HEAD has pointed. As long as a commit appears in it, you can bring it back.

$ git reflog
9a1c4e7 HEAD@{0}: reset: moving to HEAD~2
b81e6d2 HEAD@{1}: commit: Add search
3f2a9c1 HEAD@{2}: commit: Add login

Entry HEAD@{1} is the commit that the reset made unreachable.

35.2 Recovering a lost commit

$ git switch -c rescue b81e6d2
$ git reset --hard b81e6d2

Creating a branch at the old hash is the safest form, because it adds a label to the commit without moving anything else. You can also reset the current branch back to the entry shown by the reflog:

$ git reset --hard HEAD@{1}

35.3 Typical rescue stories

SituationWhat to do
Reset too farFind the old tip in git reflog and reset to it
Deleted a branch by mistakeFind its last commit in the reflog and git switch -c name <hash>
Bad rebaseFind the entry before the rebase started and reset to it
Commits made in a detached HEADThe reflog lists them; create a branch at the hash

35.4 Per-branch reflog

$ git reflog show feature

Each branch also has its own history of movements.

35.5 How long entries last

Reflog entries are kept for a limited time, by default about 90 days for reachable entries and 30 days for unreachable ones, after which Git's clean-up can remove them. Recover work soon rather than later.

35.6 When the reflog is not enough

Work that was never committed is not in the reflog. A file you edited and discarded with git restore cannot be recovered by Git. Commit early and often to give Git something to remember. For objects not reachable even from the reflog, git fsck --lost-found can list dangling commits, which is a last resort.

35.7 Common mistakes

  • Panicking and running more commands. Stop and read the reflog first.
  • Expecting to recover uncommitted work. Git cannot restore what it never saw.
  • Waiting weeks. Old unreachable entries are eventually cleaned up.
Quick recap
  • The reflog records where HEAD and branches pointed.
  • Find the lost commit hash in git reflog, then create a branch at it.
  • Entries expire after a while, so act soon.
  • Uncommitted work cannot be recovered from the reflog.
