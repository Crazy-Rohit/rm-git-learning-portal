Git hooks

Hooks are small scripts that Git runs automatically at key moments, so mistakes are stopped before they reach the team.

34.1 What a hook is

A hook is a script that Git starts when something happens, such as just before a commit. If the script exits with an error, Git cancels the action. Hooks live in .git/hooks/.

$ ls .git/hooks
applypatch-msg.sample  pre-commit.sample  pre-push.sample  commit-msg.sample

Git ships samples ending in .sample. Remove the suffix to activate one.

34.2 Useful hooks

HookRunsTypical use
pre-commitBefore a commit is madeLint code, block secrets, run fast tests
commit-msgAfter you write a messageCheck message format
pre-pushBefore a pushRun the full test suite
post-mergeAfter a mergeReinstall dependencies

34.3 A simple pre-commit hook

This script refuses any commit that includes a file called .env.

#!/bin/sh
if git diff --cached --name-only | grep -q '^\.env$'; then
  echo "Blocked: .env must not be committed."
  exit 1
fi

Save it as .git/hooks/pre-commit and make it executable.

$ chmod +x .git/hooks/pre-commit
$ git add .env
$ git commit -m "Add settings"
Blocked: .env must not be committed.

34.4 Hooks are not shared

Everything inside .git stays on your machine, so teammates do not receive your hooks. Two common ways to share them:

  • Keep hooks in a folder in the repository and point Git at it: git config core.hooksPath .githooks.
  • Use a hook manager such as the pre-commit framework (Python), Husky (JavaScript) or lefthook.
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-added-large-files
$ pip install pre-commit
$ pre-commit install

From now on those checks run on every commit.

34.5 Skipping a hook

$ git commit --no-verify -m "Emergency fix"

Use this rarely. Anyone can bypass local hooks, so important rules should also exist in CI (Chapter 31) and branch protection (Chapter 33).

34.6 Common mistakes

  • Forgetting chmod +x. A hook that is not executable is silently ignored.
  • Slow hooks. If a commit takes thirty seconds, people will skip them. Keep pre-commit fast and put long tests in pre-push or CI.
  • Relying only on local hooks. They are a convenience, not security.
Quick recap
  • Hooks are scripts Git runs at set moments; a non-zero exit cancels the action.
  • pre-commit, commit-msg and pre-push are the most useful.
  • Hooks in .git/hooks are not shared; use core.hooksPath or a hook manager.
  • Back local hooks with CI checks.
