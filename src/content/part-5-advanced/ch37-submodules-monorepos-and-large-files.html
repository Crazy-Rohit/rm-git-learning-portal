Submodules, monorepos and large files

Big projects need tools for sharing code between repositories and storing large files, and each has trade-offs.

37.1 Submodules: a repository inside a repository

A submodule pins another repository at an exact commit inside yours. It is useful when you depend on a shared library that lives in its own repository.

$ git submodule add https://github.com/example/shared-lib.git libs/shared-lib
$ git commit -m "Add shared-lib as a submodule"

Git records the submodule's address in .gitmodules and the commit it points to. Cloning needs one more flag, or the folder will be empty.

$ git clone --recurse-submodules https://github.com/you/app.git
$ git submodule update --init --recursive
$ git submodule update --remote
ProsCons
Exact, reproducible version of the dependencyExtra steps for every clone and update
Library stays in one placeEasy to forget to commit the new pointer

Often a package manager (pip, npm, Maven) is simpler for libraries. Consider submodules when you need the source and its history together.

37.2 Monorepo or many repositories

MonorepoMany repositories
StructureAll projects in one repositoryOne repository per project
Sharing codeEasy, one commit can change several partsNeeds published packages
PermissionsHarder to restrict one partPer-repository access
ScaleNeeds tooling as it growsMany repositories to manage
Used byLarge engineering teams with strong toolingMost small teams

Very large repositories can use sparse checkout, which downloads only some folders, and partial clone, which downloads file contents on demand.

$ git clone --filter=blob:none https://github.com/example/big-repo.git
$ git sparse-checkout set services/api

37.3 Large files and Git LFS

Git stores every version of every file forever, so large binary files such as videos, datasets and design files make a repository huge. GitHub warns about files over 50 MB and blocks files over 100 MB. Git LFS (Large File Storage) keeps lightweight pointer files in Git and stores the real content on a separate server.

$ git lfs install
$ git lfs track "*.psd"
$ git add .gitattributes
$ git add design.psd
$ git commit -m "Add design file with LFS"

Tracking rules are saved in .gitattributes, which you commit.

Warning

Track files with LFS before committing them. Files already in history stay there and keep the repository large. Moving them later needs git lfs migrate, which rewrites history.

GitHub gives each account a limited LFS storage and bandwidth allowance, so check the current limits for your plan. Datasets that change often are better kept in dedicated tools for data versioning or in cloud storage.

37.4 Common mistakes

  • Cloning a repository with submodules and getting empty folders. Use --recurse-submodules.
  • Committing large datasets to normal Git. Use LFS or external storage.
  • Moving to a monorepo without build tooling. Builds and tests become slow.
Quick recap
  • Submodules pin another repository at a specific commit.
  • Clone with --recurse-submodules.
  • Monorepos suit big teams with tooling; separate repositories suit most others.
  • Use Git LFS for large binary files, and set it up before committing them.
