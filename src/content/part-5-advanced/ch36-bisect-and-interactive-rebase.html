Bisect and interactive rebase

Bisect finds the commit that introduced a bug, and interactive rebase lets you polish your commits before you share them.

36.1 git bisect: find the bad commit

Suppose a bug appeared somewhere in the last 200 commits. Checking each would take hours. Bisect performs a binary search, halving the range each time, so about eight checks are enough for 200 commits.

$ git bisect start
$ git bisect bad
$ git bisect good v1.2.0
Bisecting: 97 revisions left to test after this (roughly 7 steps)
$ git bisect good
$ git bisect bad
b81e6d2 is the first bad commit
$ git bisect reset

36.2 Automating bisect

If you have a test that fails on the bug, let Git run it.

$ git bisect start HEAD v1.2.0
$ git bisect run pytest tests/test_checkout.py

Git repeats the test at each step and reports the first failing commit by itself.

36.3 Interactive rebase: polish history

Before opening a pull request you may want to merge small "fix typo" commits or reword unclear messages. Interactive rebase does that on your own, unshared commits.

$ git rebase -i HEAD~4

An editor opens with a list, oldest commit first.

pick 3f2a9c1 Add login form
pick 8e4c1b7 Fix typo
pick a3b9d21 Add validation
pick 7b1d2e4 Fix validation bug

Change the word at the start of each line to say what to do.

CommandEffect
pickKeep the commit as it is
rewordKeep it but change the message
editStop so you can change the commit's content
squashMerge into the previous commit and combine the messages
fixupMerge into the previous commit and discard this message
dropDelete the commit
 
pick 3f2a9c1 Add login form
fixup 8e4c1b7 Fix typo
pick a3b9d21 Add validation
fixup 7b1d2e4 Fix validation bug

Save and close. Four commits become two clean ones. You can also reorder commits by moving their lines.

36.4 Fixup commits

$ git commit --fixup 3f2a9c1
$ git rebase -i --autosquash HEAD~5

--fixup records a correction aimed at an earlier commit, and --autosquash arranges the list for you.

36.5 Safety

Caution

Interactive rebase rewrites history, so use it only on commits that nobody else has. If something goes wrong, run git rebase --abort, or recover through the reflog (Chapter 35).

36.6 Common mistakes

  • Rebasing shared commits. The golden rule from Chapter 17 applies.
  • Marking the first line as squash. There is no earlier commit to merge into.
  • Not knowing a good commit for bisect. Use a release tag or an older commit that you know worked.
Quick recap
  • git bisect binary-searches history to find the commit that introduced a bug.
  • git bisect run <command> automates the search.
  • git rebase -i lets you reword, squash, fixup, drop and reorder commits.
  • Only rewrite history that is still private.

Each step halves the range, so the number is about log2(1000).
