Issues, labels and projects

Issues record bugs and ideas, and projects arrange them into a board, so the whole team can see what is happening.

27.1 What an issue is

An issue is a discussion thread about a bug, a task or a feature request. It has a title, a description, comments, an assignee and labels. Issues are numbered, such as #12, and you can refer to them from commits and pull requests.

27.2 Writing a good issue

A good bug report lets someone reproduce the problem without asking questions.

Title: Login button does nothing on Safari

Steps to reproduce
1. Open the login page in Safari 17
2. Enter a valid email and password
3. Click "Log in"

Expected: the dashboard opens
Actual: nothing happens and no error appears

Environment: macOS 14, Safari 17.2

27.3 Labels, assignees and milestones

FeaturePurposeExample
LabelsCategorise issuesbug, enhancement, documentation, good first issue
AssigneesSay who is working on it@priya
MilestonesGroup issues for a release or deadlinev1.2.0
ProjectsShow issues on a boardTo do, In progress, Done

GitHub provides default labels, and you can add your own. The good first issue label is a convention that helps newcomers find easy tasks.

27.4 Linking issues and code

Mention an issue anywhere with #12. Use closing keywords in a pull request description or a commit message:

Fix login on Safari

Closes #12

The keywords close, fix and resolve, in their various forms, close the issue when the change reaches the default branch.

27.5 Mentions and references

  • @username notifies a person.
  • #12 links to an issue or pull request.
  • A full commit hash links to that commit.

27.6 GitHub Projects

A project is a board or table that collects issues and pull requests from one or more repositories. You can arrange them into columns such as Backlog, In progress, In review and Done, and add fields like priority or sprint.

27.7 Issue templates

Files inside .github/ISSUE_TEMPLATE/ give reporters a form to fill in, which makes reports more complete.

27.8 Discussions

For open-ended questions and ideas that are not tasks, repositories can turn on Discussions, a forum-style space separate from issues.

27.9 Common mistakes

  • Vague issues like "it is broken". Add steps, expected and actual results.
  • Duplicates. Search before you open a new issue.
  • Issues without owners. Assign someone, or label them as available.
Quick recap
  • Issues track bugs, tasks and ideas; they are numbered and searchable.
  • Labels, assignees and milestones organise them.
  • Closes #n links a pull request to an issue and closes it on merge.
  • Projects show work as a board.

Practice exercise
  • Open an issue in your practice repository using the bug-report layout above.
  • Add two labels, assign yourself, and create a three-column project board.
  • Reference the issue from a pull request with Closes #<number>.
