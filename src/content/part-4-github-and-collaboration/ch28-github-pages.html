GitHub Pages

GitHub Pages turns a repository into a free website, with no server to manage.

28.1 What Pages gives you

GitHub Pages hosts static sites made of HTML, CSS and JavaScript files. It is free, serves over HTTPS and updates every time you push. It is ideal for portfolios, project documentation and landing pages. It cannot run server-side code or a database, which is why this handbook's interactive parts all run in the browser.

28.3 Publishing your first page

<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>My first page</title></head>
<body>
  <h1>Hello from GitHub Pages</h1>
</body>
</html>
$ git add index.html
$ git commit -m "Add home page"
$ git push origin main

In the repository, open Settings, choose Pages, and under Build and deployment pick Deploy from a branch. Select main and the / (root) folder, then save. GitHub shows the address when the deployment finishes.

28.4 Using GitHub Actions to deploy

If your site needs a build step, for example a React app or a static site generator, choose GitHub Actions as the source and add a workflow that builds the site and publishes the output. Chapter 31 introduces workflows.

28.5 Custom domains

In Settings, then Pages, you can enter your own domain. Create the matching DNS record at your domain registrar, and GitHub provides the HTTPS certificate.

28.6 Handy tips

  • Put images and styles in folders and link them with relative paths.
  • A file named 404.html becomes your custom error page.
  • A .nojekyll file turns off the default Jekyll processing, which helps with plain HTML projects that have folders starting with an underscore.

28.7 Common mistakes

  • Missing index.html. Pages shows a 404 without it.
  • Wrong path casing. File names are case sensitive on GitHub: Logo.png is not logo.png.
  • Expecting instant updates. A deployment can take a minute or two.
  • Putting secrets in a Pages repository. Everything published is public.
Quick recap
  • Pages hosts free static sites straight from a repository.
  • User sites live at username.github.io; project sites in a sub-path.
  • Enable it under Settings, then Pages.
  • Use Actions to build sites that need a build step.
