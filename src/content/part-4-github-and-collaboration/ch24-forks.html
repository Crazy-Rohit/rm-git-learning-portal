Forks

A fork is your own copy of someone else's repository on GitHub, which lets you propose changes to a project you do not own.

24.1 Why forks exist

You cannot push to a stranger's repository. A fork copies it into your account, where you have full control. You change your copy, then ask the owner to take your changes through a pull request (Chapter 25).

24.2 Fork versus clone

ForkClone
Where it happensOn GitHub, copy to your accountOn your computer
Needs permissionNo, if the repository is publicNo, if you can read it
PurposeGet your own writable copy onlineGet files and history locally

You usually do both: fork on GitHub, then clone your fork.

24.3 Forking step by step

  1. Open the project's page and select Fork.
  2. Choose your account and create the fork.
  3. Clone your fork, not the original.
$ git clone git@github.com:your-username/project.git
$ cd project
$ git remote -v
origin  git@github.com:your-username/project.git (fetch)

24.4 Adding the upstream remote

The original repository is usually called upstream. Add it so you can pull in its new work.

$ git remote add upstream https://github.com/original-owner/project.git
$ git remote -v
origin    git@github.com:your-username/project.git (fetch)
upstream  https://github.com/original-owner/project.git (fetch)

24.5 Keeping your fork up to date

$ git fetch upstream
$ git switch main
$ git merge upstream/main
$ git push origin main

GitHub also has a Sync fork button on your fork's page that does the same thing without the command line.

Tip

Never work directly on your fork's main. Create a branch for each change, and keep main as a clean mirror of upstream.

24.6 Common mistakes

  • Cloning the original instead of your fork. You cannot push to it.
  • Forgetting to sync. Your changes drift away from the project and conflict later.
  • Forking when you are already a collaborator. If you have write access, a branch in the same repository is simpler.
Quick recap
  • A fork is your own online copy of another repository.
  • Clone your fork, and add the original as upstream.
  • Keep main in sync with git fetch upstream and a merge.
  • Work on branches, then open a pull request to the original.
Check yourself

1. Which repository should you clone to contribute to a project you do not own?

Practice exercise
  • Fork a practice repository, clone it, and add the upstream remote.
  • Run git remote -v and check you see both.
