Authentication: SSH keys and tokens

GitHub needs to know who you are before it accepts a push, and there are two safe ways to prove it: SSH keys and access tokens.

23.1 Why passwords no longer work

Since 2021 GitHub does not accept your account password for Git operations over HTTPS. You use either a personal access token or an SSH key. Both are safer, because they can be limited and revoked without changing your password.

23.2 Option 1: SSH keys

An SSH key is a pair of files. The private key stays secret on your computer. The public key is given to GitHub. GitHub uses the pair to check that you hold the private key, without the secret ever travelling.

$ ssh-keygen -t ed25519 -C "you@example.com"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/you/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):
$ eval "$(ssh-agent -s)"
$ ssh-add ~/.ssh/id_ed25519
$ cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3Nz...example you@example.com

Copy the whole line that starts with ssh-ed25519. On GitHub open Settings, then SSH and GPG keys, choose New SSH key, paste it and save.

$ ssh -T git@github.com
Hi your-username! You've successfully authenticated, but GitHub does not provide shell access.

Now use the SSH form of the address:

$ git remote set-url origin git@github.com:your-username/hello-git.git
Important

Share only the file ending in .pub. The file without .pub is your private key. Never email it, paste it in chat or commit it.

Add a passphrase when asked. It protects the key if your laptop is stolen.

23.3 Option 2: Personal access tokens

A token is a long random string that acts like a password with limited powers. GitHub offers two kinds. Fine-grained tokens can be limited to selected repositories and permissions, and GitHub recommends them where possible. Classic tokens use broad scopes such as repo.

  1. Open Settings, then Developer settings, then Personal access tokens.
  2. Create a token, choose the repositories and permissions, and set an expiry date.
  3. Copy it immediately; GitHub shows it only once.
  4. When Git asks for a password over HTTPS, paste the token.

Git Credential Manager, which comes with Git for Windows and is available on other systems, stores the token safely so you do not paste it every time.

23.5 GitHub CLI shortcut

The GitHub command-line tool gh can handle the login for you.

$ gh auth login

23.6 Common mistakes

  • Committing a token or private key. Treat it as leaked and revoke it at once.
  • Using a token with far too many permissions. Give the minimum.
  • Mixing HTTPS and SSH remotes. An SSH key does nothing if your remote is an https:// address.
Quick recap
  • Use SSH keys or personal access tokens; passwords are no longer accepted.
  • Keep the private key secret and give GitHub only the .pub file.
  • Fine-grained tokens with expiry dates are safest.
  • ssh -T git@github.com tests an SSH setup.
Check yourself

1. Which file do you upload to GitHub for SSH access?

The .pub file is the public half; the other is your secret.

Practice exercise
  • Generate an ed25519 key with a passphrase and add the public key to GitHub.
  • Run ssh -T git@github.com and confirm the greeting.
  • Switch your remote to the SSH address and push a commit.
