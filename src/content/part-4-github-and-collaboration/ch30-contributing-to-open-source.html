Contributing to open source

Open source runs on small contributions from strangers, and the workflow you have learned is exactly how they are made.

30.1 Why contribute

Contributing to open source teaches you to read real code, work with reviewers and communicate in public. Your commits and merged pull requests also become a visible record of your skills on your GitHub profile.

30.2 Finding a first project

  • Search GitHub issues with the label good first issue or help wanted.
  • Start with tools you already use, and look at their documentation for typos or gaps.
  • Check that the project is alive: recent commits, answered issues, and a CONTRIBUTING.md.

30.3 The complete workflow

$ git clone git@github.com:your-username/project.git
$ cd project
$ git remote add upstream https://github.com/owner/project.git
$ git switch -c fix-docs-typo
$ git add docs/install.md
$ git commit -m "Fix typo in installation guide"
$ git push -u origin fix-docs-typo

30.4 Small contributions count

You do not need to write a new feature. These are all welcome and valuable:

  • Correcting documentation, typos and broken links.
  • Adding a missing example.
  • Reproducing a bug and adding details to the issue.
  • Improving tests.
  • Translating text.

30.5 Good etiquette

  • Read the existing issues and pull requests first, so you do not duplicate work.
  • Ask before starting a large change.
  • Keep pull requests small and on topic.
  • Be patient. Maintainers are often volunteers.
  • Say thank you, and accept feedback gracefully.

30.6 When your pull request is not accepted

It happens, and it is not personal. The project may have a different direction. Ask what would make the change acceptable, learn from it, and try another issue.

30.7 Becoming a maintainer

Contributors who help regularly are sometimes invited to review and merge. As a maintainer, you will triage issues, review pull requests and keep documentation current, which makes your GitHub activity richer and more visible.

30.8 Common mistakes

  • Opening a pull request without reading the contribution guide. It may be closed quickly.
  • One giant pull request. Split it up.
  • Working on main in your fork. Always use a branch.
Quick recap
  • Look for good first issue labels and active projects.
  • Fork, clone, branch, change, push and open a pull request.
  • Documentation and test improvements are real contributions.
  • Be patient and respectful with maintainers.

Practice exercise
  • Find an open-source project with a good first issue label that interests you.
  • Read its CONTRIBUTING.md and write down the steps it asks for.
  • Send a small documentation fix as a pull request.
