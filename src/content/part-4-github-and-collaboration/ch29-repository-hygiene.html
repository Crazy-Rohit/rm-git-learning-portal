Repository hygiene

A well-kept repository welcomes newcomers and protects the project with a clear README, licence and contribution rules.

29.1 The README: the front door

The README is the first thing visitors see. GitHub displays it under the file list. A good README answers four questions in under a minute: What is this? How do I run it? How do I use it? How do I help?

# Project name

One sentence about what it does.

## Install
## Usage
## Contributing
## Licence

Add a screenshot, a short code example and badges for build status if you have them. Write in Markdown.

29.3 Choosing a licence

Without a licence, nobody has permission to reuse your code, even if it is public. Add a LICENSE file. GitHub can create one from a template when you add a file.

LicenceIn short
MITVery permissive. Reuse for anything, keep the copyright notice
Apache 2.0Permissive, with an explicit patent grant
GPL 3.0Reusers must also release their changes under the GPL

This is a simplified summary, not legal advice. For serious projects read the licence text or ask someone qualified.

29.4 Community files

FilePurpose
CONTRIBUTING.mdHow to report bugs, set up the project and send changes
CODE_OF_CONDUCT.mdHow people are expected to behave
SECURITY.mdHow to report a vulnerability privately
.github/ISSUE_TEMPLATE/Forms for new issues
.github/pull_request_template.mdChecklist for new PRs

GitHub shows these in the Community standards page of a repository and links them from the issue and PR screens.

29.5 Description, topics and social image

Fill in the one-line About description and add topics such as python or git-tutorial. Topics help people find your project in search.

29.6 A profile README

Create a public repository whose name is exactly your username, and add a README.md. GitHub shows it at the top of your profile, which is a good place for a short introduction and links to your best work.

29.7 Common mistakes

  • No licence. People cannot legally reuse the code.
  • A README that only says the project name. Explain installation and usage.
  • Committing generated files and secrets. Use .gitignore.
Quick recap
  • The README should explain what, how to run, how to use and how to contribute.
  • Add a LICENSE; MIT, Apache 2.0 and GPL 3.0 are common.
  • CONTRIBUTING.md, templates and a code of conduct welcome contributors.
  • A repository named after you becomes your profile README.
