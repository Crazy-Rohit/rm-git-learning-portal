Push, pull and fetch

These three commands move commits between your computer and GitHub, and knowing how they differ avoids most beginner surprises.

22.1 Push: send your commits

$ git push
Enumerating objects: 5, done.
To https://github.com/your-username/hello-git.git
   3f2a9c1..9a1c4e7  main -> main

Push uploads commits that the remote does not have yet. After the first git push -u, a plain git push is enough.

22.2 Fetch: look without touching

$ git fetch
From https://github.com/your-username/hello-git
   9a1c4e7..b81e6d2  main       -> origin/main

Fetch downloads new commits but does not change your working files or your branch. They are stored in a remote-tracking branch named origin/main. You can inspect them before deciding what to do.

$ git log main..origin/main --oneline
b81e6d2 Add contact page

22.3 Pull: fetch and merge

git pull is a shortcut: it runs git fetch and then merges the result into your current branch.

$ git pull
Updating 9a1c4e7..b81e6d2
Fast-forward
 contact.html | 8 ++++++++

Use git pull --rebase if you prefer a straight history (Chapter 17).

22.4 When a push is rejected

$ git push
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs
hint: Updates were rejected because the remote contains work that
hint: you do not have locally.

Someone else pushed before you. The fix is always the same: bring in their work first.

22.5 Force pushing

$ git push --force-with-lease

A force push overwrites the remote history. You may need one after a rebase or an amend. Use --force-with-lease, which stops if someone else pushed in the meantime. Never force-push to main or any branch your team shares.

22.6 Other useful push commands

CommandPurpose
git push origin featurePush a named branch
git push -u origin featurePush a new branch and link it
git push origin --delete featureDelete a remote branch
git fetch --pruneRemove references to deleted remote branches
git pull --ff-onlyPull only if no merge is needed

22.7 Common mistakes

  • Pushing without pulling first. Make git pull a habit before you start work.
  • Using --force instead of --force-with-lease. The first can erase a teammate's commits.
  • Thinking fetch changes your files. It does not; only merge, rebase or pull do.
Quick recap
  • git push sends your commits; git fetch downloads without changing your files.
  • git pull is fetch plus merge (or rebase).
  • A rejected push means you must pull the remote work first.
  • Prefer --force-with-lease and never force-push shared branches.
Check yourself

1. Which command downloads new commits without changing your working files?

Practice exercise
  • In two clones of the same repository, push a commit from one and git fetch in the other.
  • Run git log main..origin/main to see the incoming commit, then git pull.
  • Create a rejected push on purpose and fix it with a pull.
