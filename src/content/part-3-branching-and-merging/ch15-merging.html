Merging

Merging brings the work of one branch into another, and Git chooses between two methods depending on how the history looks.

15.1 The basic command

Move to the branch that should receive the work, then merge the other one in.

$ git switch main
$ git merge feature-login

The rule to remember: you merge into the branch you are standing on.

15.2 Fast-forward merge

If main has not moved since you branched, Git simply slides the main pointer forward. No new commit is needed.

$ git merge feature-login
Updating 3f2a9c1..b81e6d2
Fast-forward
 login.py | 12 ++++++++++++
 1 file changed, 12 insertions(+)

15.3 Three-way merge

If both branches have new commits, a simple slide is impossible. Git compares three snapshots: the common ancestor and the two branch tips. It then creates a merge commit with two parents.

$ git merge feature-login
Merge made by the 'ort' strategy.
 login.py | 12 ++++++++++++
 1 file changed, 12 insertions(+)

Git opens your editor with a default message such as "Merge branch 'feature-login'". Save and close to finish.

15.4 Controlling the style of merge

OptionEffect
--no-ffAlways create a merge commit, even when a fast-forward is possible
--ff-onlyRefuse to merge unless a fast-forward is possible
--squashCombine all branch changes into one staged change, then you commit it yourself
--abortCancel a merge that is in progress

Teams choose between them. --no-ff keeps a visible record of each feature. --squash keeps main tidy with one commit per feature. GitHub offers the same three choices on pull requests (Chapter 25).

15.5 After merging: clean up

$ git branch -d feature-login
Deleted branch feature-login (was b81e6d2).

The commits are safe, because they are now part of main. Only the label is removed.

15.6 Common mistakes

  • Merging in the wrong direction. Check which branch you are on with git status.
  • Merging with uncommitted changes. Commit or stash first.
  • Never deleting old branches. They clutter the list. Delete them once merged.
Quick recap
  • You merge a branch into the one you are on: git merge <branch>.
  • Fast-forward just moves the pointer; a three-way merge makes a merge commit.
  • --no-ff, --ff-only and --squash change how the history looks.
  • Delete merged branches with git branch -d.
