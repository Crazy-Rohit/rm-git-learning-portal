Merge conflicts

A conflict happens when two branches change the same lines, and Git asks you to decide what the result should be.

16.1 Why conflicts happen

Git merges automatically when branches change different parts of a file. When both branches edit the same lines, Git cannot know which version you want. It stops and asks you. That is not an error, only a question that needs a human answer.

16.2 What a conflict looks like

$ git merge feature-login
Auto-merging app.py
CONFLICT (content): Merge conflict in app.py
Automatic merge failed; fix conflicts and then commit the result.

Open the file. Git has marked the conflicting area.

<<<<<<< HEAD
greeting = "Hello, user!"
=======
greeting = "Welcome back!"
>>>>>>> feature-login
MarkerMeaning
<<<<<<< HEADStart of your version (the branch you are on)
=======Divider between the two versions
>>>>>>> feature-loginEnd of the incoming version

16.3 Resolving it step by step

Suppose you decide to combine both greetings. Edit the file to the final text you want and remove the markers.

greeting = "Welcome back, user!"
$ git add app.py
$ git commit
[main 4d5e6f7] Merge branch 'feature-login'

16.4 Useful commands during a conflict

CommandUse
git statusSee which files still conflict
git diffSee remaining conflicts
git merge --abortCancel and return to the state before the merge
git checkout --ours fileKeep your side of one file entirely
git checkout --theirs fileKeep the incoming side of one file entirely
git mergetoolOpen a visual merge tool
Tip

Visual Studio Code shows buttons above each conflict: Accept Current, Accept Incoming, Accept Both. Many people find this easier than editing markers by hand.

16.5 Making conflicts less likely

  • Pull the latest main into your branch often.
  • Keep branches short-lived and focused.
  • Talk to teammates before large refactors or file moves.
  • Keep functions and files small so edits rarely overlap.

16.6 Seeing more context

By default Git shows only two sides. The zdiff3 style also shows the common ancestor, which often makes the right choice obvious.

$ git config --global merge.conflictStyle zdiff3

16.7 Common mistakes

  • Leaving markers in the file. Search for <<<<<<< before you commit. A project with markers will not run.
  • Accepting one side without reading. You may silently throw away a teammate's work.
  • Panicking. git merge --abort always takes you back to safety.
Quick recap
  • Conflicts occur when both branches change the same lines.
  • Markers show your version, a divider and the incoming version.
  • Edit, remove markers, git add, then commit.
  • git merge --abort cancels the merge.

Practice exercise
  • Create a conflict on purpose: edit the same line differently on two branches and merge.
  • Resolve it by combining both versions and finish the merge.
  • Repeat, then cancel the second attempt with git merge --abort.
