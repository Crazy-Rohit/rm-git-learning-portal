Rebase

Rebase replays your commits on top of another branch, which gives a straight, easy-to-read history.

17.1 The idea

Merging joins two histories with a merge commit. Rebasing takes your branch's commits and re-applies them one by one on top of the latest main, as if you had started your work from there.

$ git switch feature
$ git rebase main
Successfully rebased and updated refs/heads/feature.

The history is now a straight line. The feature commits have the same changes but new hashes, because their parent changed.

17.2 Merge or rebase

MergeRebase
HistoryKeeps the true branching shapeGives a straight line
Extra commitsAdds a merge commitAdds none
Rewrites commitsNoYes (new hashes)
Safe on shared branchesYesNo
Typical useJoining finished workUpdating your own branch before a pull request

17.3 Rebase conflicts

Conflicts can appear while commits are replayed. Resolve them as in Chapter 16, then continue.

$ git add app.py
$ git rebase --continue
$ git rebase --abort
$ git rebase --skip
  • --continue carries on after you fixed the files.
  • --abort returns to how things were before the rebase.
  • --skip drops the commit that is causing trouble.

17.4 The golden rule of rebase

Caution

Never rebase commits that other people already have. Rebase creates new commits with new hashes. If teammates built on the old ones, their history and yours no longer match, and fixing it is painful.

Rebase your own local or personal-branch commits freely. Do not rebase main or any shared branch.

17.5 Pull with rebase

A normal git pull can add merge commits. This keeps your local history linear instead:

$ git pull --rebase
$ git config --global pull.rebase true

17.6 Common mistakes

  • Rebasing a shared branch. Follow the golden rule.
  • Force-pushing after a rebase without care. Use git push --force-with-lease, which refuses to overwrite work you have not seen.
  • Rebasing in a panic during conflicts. Abort and look at the state first.
Quick recap
  • Rebase replays your commits on top of another branch.
  • It creates new commits and a straight history.
  • Never rebase commits that are already shared.
  • Use --continue, --abort or --skip during conflicts.
