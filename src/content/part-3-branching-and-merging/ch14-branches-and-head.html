Branches and HEAD

A branch is a separate line of work, so you can try ideas without disturbing the stable version of your project.

14.1 The idea: parallel drafts

Writing a report, you might copy the document to try a risky rewrite. If it works you keep it, and if not you throw the copy away. A branch gives you that without copying any files. Your stable work stays on main, while the experiment lives on its own branch.

Because a branch is only a pointer to a commit (Chapter 13), creating one is instant and costs almost no space.

14.2 Creating and listing branches

$ git branch feature-login
$ git branch
  feature-login
* main

The * marks the branch you are on. Creating a branch does not move you onto it.

14.3 Switching branches

$ git switch feature-login
Switched to branch 'feature-login'
$ git switch -c feature-search
Switched to a new branch 'feature-search'

git switch -c <name> creates and switches in one step, which is the form you will use most.

Note

Older tutorials use git checkout <branch> and git checkout -b <branch>. They still work. switch was added in 2019 to give branch changes a clearer name.

When you switch, Git rewrites the files in your working directory to match that branch. Work you committed on another branch seems to vanish and returns when you switch back.

14.4 HEAD: where you are

HEAD points to the branch you are on, and that branch points to its latest commit. Each new commit moves the branch forward, and HEAD follows.

14.5 Everyday branch commands

CommandWhat it does
git branchList local branches
git branch -aList local and remote branches
git branch -m old newRename a branch
git branch -d nameDelete a merged branch
git branch -D nameForce-delete a branch, even if unmerged
git switch -Jump back to the previous branch
git branch -vvShow each branch's latest commit and upstream

14.6 Detached HEAD

If you check out a commit hash or a tag, HEAD points straight at a commit, not a branch. Git calls this a detached HEAD.

$ git switch --detach 3f2a9c1
HEAD is now at 3f2a9c1 Add README

You can look around safely. But a commit made here belongs to no branch and can be lost. To keep the work, give it a branch:

$ git switch -c rescue-work

To leave without keeping anything, run git switch main.

14.7 Naming branches

  • Use short lowercase names with hyphens: fix-login-bug.
  • Group by purpose with a prefix: feature/search, bugfix/crash, docs/readme.
  • Avoid spaces and personal names.

14.8 Uncommitted changes when switching

If your edits do not touch files that differ between the branches, they travel with you. If they would be overwritten, Git refuses to switch and asks you to commit or stash first (Chapter 19).

14.9 Common mistakes

  • Committing on main by accident. Check git branch before you start.
  • Forgetting which branch you are on. Use git status or a prompt that shows it.
  • Deleting an unmerged branch with -D. You may lose the only copy of that work.
Quick recap
  • A branch is a movable pointer to a commit; creating one is instant.
  • git switch -c name creates and enters a branch.
  • HEAD points to your current branch; commits move it forward.
  • Detached HEAD means HEAD points at a commit; create a branch to keep work done there.
