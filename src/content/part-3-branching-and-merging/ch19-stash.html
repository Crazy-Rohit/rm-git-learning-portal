Stash

Stash puts your unfinished work on a shelf so you can change branches with a clean working directory.

19.1 The problem

You are halfway through a change when a colleague asks for an urgent fix on another branch. Your work is not ready to commit, and Git refuses to switch because it would overwrite your edits. Stash solves exactly this.

19.2 Basic use

$ git stash
Saved working directory and index state WIP on feature: 8e4c1b7 Add form
$ git switch main

Your working directory is now clean. Do the urgent work, then come back.

$ git switch feature
$ git stash pop

pop re-applies the stashed changes and removes them from the stash.

19.3 Commands you will use

CommandWhat it does
git stash push -m "message"Stash with a helpful name
git stash listShow all stashes
git stash popRe-apply the newest stash and delete it
git stash applyRe-apply but keep it in the list
git stash dropDelete the newest stash
git stash show -pShow what the stash contains
git stash -uInclude untracked files
git stash branch nameCreate a branch from a stash
 
$ git stash list
stash@{0}: On feature: half-finished form
stash@{1}: WIP on main: a3b9d21 Fix typo
$ git stash apply stash@{1}

19.4 What stash does not include

By default stash saves changes to tracked files only. New files that Git has never seen stay behind unless you add -u. Ignored files need -a.

19.5 Conflicts when applying

If the branch changed since you stashed, pop can conflict. Resolve it like any merge conflict. After a conflict, Git keeps the stash, so nothing is lost.

19.6 Common mistakes

  • Stashing and forgetting. Stashes are easy to lose track of. Give each a message and clear them regularly.
  • Expecting new files to be stashed. Use -u.
  • Using stash as long-term storage. For work you want to keep, make a branch and commit.
Quick recap
  • git stash shelves uncommitted work; git stash pop brings it back.
  • Use -m to label stashes and -u for untracked files.
  • apply keeps the stash; pop removes it.
  • For long-lived work, commit on a branch instead.
