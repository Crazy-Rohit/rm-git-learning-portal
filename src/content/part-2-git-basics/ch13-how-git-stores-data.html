How Git stores data

Git is a database of snapshots identified by hashes, and seeing its structure makes the commands feel logical.

13.1 Snapshots, not differences

Older tools stored a list of changes for every file. Git instead stores a snapshot of the whole project at each commit. Unchanged files are not copied again; the new snapshot simply points to the version that already exists. This is why branching and switching are so fast.

13.2 The four object types

Git stores everything as objects inside .git/objects, each named by a hash.

ObjectStoresAnalogy
BlobThe contents of one fileA page of text
TreeA folder: a list of names pointing to blobs and other treesA table of contents
CommitA pointer to a tree, plus author, date, message and parentA dated photo with a caption
TagA named pointer, often to a commitA bookmark

13.3 Hashes: the fingerprint of content

Every object is named by a hash of its contents. By default Git uses SHA-1, a 40-character hexadecimal code. Identical content always gives an identical hash, and any tiny change produces a completely different one.

$ echo "hello" | git hash-object --stdin
ce013625030ba8dba906f756967f9e9ca394464a

This is why Git history is trustworthy: a commit's hash depends on its content and its parent's hash, so changing an old commit changes every hash after it. Git also has experimental support for SHA-256 as a stronger option.

13.4 Looking inside

$ git cat-file -t 3f2a9c1
commit
$ git cat-file -p 3f2a9c1
tree 8c3a1b9d0e7f2a4b6c5d8e9f0a1b2c3d4e5f6a7b
author Your Name <you@example.com> 1759640000 +0530
committer Your Name <you@example.com> 1759640000 +0530

Add README
$ git cat-file -p 8c3a1b9
100644 blob 2f8d6a1b7c9e0a3b5d4c6e8f9a0b1c2d3e4f5a6b	README.md

-t shows the type and -p pretty-prints the content. The hashes above are examples; yours will differ.

13.5 Branches and HEAD are just pointers

A branch is a tiny file that holds one commit hash. HEAD is a file that says which branch you are on.

$ cat .git/HEAD
ref: refs/heads/main
$ cat .git/refs/heads/main
9a1c4e7d2b8f0c3a5e6d7f8a9b0c1d2e3f4a5b6c

Creating a branch means writing a 41-byte file, which explains why it is instant. Chapter 14 builds on this.

13.6 Common mistakes

  • Thinking commits store only the differences. They store full snapshots, efficiently shared.
  • Editing files inside .git. Use Git commands instead, so the data stays consistent.
Quick recap
  • Git stores snapshots as objects: blobs, trees, commits and tags.
  • Objects are named by a hash of their content.
  • A branch is a pointer to a commit; HEAD points to the current branch.
  • Hashes make history tamper-evident.
