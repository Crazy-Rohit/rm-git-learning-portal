Ignoring files

A .gitignore file tells Git which files to leave alone, such as secrets, build output and temporary files.

10.1 Why some files must not be tracked

Some files should never enter your history:

  • Passwords, API keys and .env files.
  • Dependencies such as node_modules/ or venv/, which can be downloaded again.
  • Build output, logs and cache files.
  • Editor or operating system files such as .DS_Store or .vscode/.

Ignoring them keeps the repository small, clean and safe.

10.2 Creating a .gitignore

Create a plain text file named .gitignore in the project root. Each line is a pattern.

# Python
__pycache__/
*.pyc
venv/

# Secrets
.env

# Logs
*.log

# Operating system
.DS_Store
$ git add .gitignore
$ git commit -m "Add .gitignore"

Commit the .gitignore itself so everyone on the team shares the same rules.

10.3 Pattern rules

PatternMatches
*.logAny file ending in .log, in any folder
build/A folder named build
/todo.txtOnly todo.txt in the project root
docs/*.pdfPDF files directly inside docs
**/tempA folder named temp at any depth
!important.logException: do not ignore this file
# commentA comment line
Note

The order matters. A later ! rule can re-include something an earlier rule ignored, but only if the parent folder itself is not ignored.

10.4 When a file is already tracked

.gitignore only affects files Git is not yet tracking. If you committed .env before ignoring it, Git keeps tracking it. Tell Git to stop, but keep the file on disk:

$ git rm --cached .env
rm '.env'
$ git commit -m "Stop tracking .env"
Caution

The file is still in your old history. If it contained a real secret, treat the secret as leaked and change it. Chapter 38 explains this.

10.5 Checking why a file is ignored

$ git check-ignore -v debug.log
.gitignore:3:*.log	debug.log
$ git status --ignored

10.6 A global ignore file

Rules for your own computer, such as editor files, belong in a global file so you do not repeat them in every project.

$ git config --global core.excludesfile ~/.gitignore_global

10.7 Ready-made templates

GitHub maintains a collection of .gitignore templates for most languages and frameworks. Start from the one that matches your stack, then adjust it. GitHub also offers to add one when you create a new repository.

10.8 Common mistakes

  • Ignoring after committing. Remember git rm --cached.
  • Ignoring a folder, then expecting an exception inside it to work. Ignore files, or use folder/* style patterns.
  • Ignoring everything with *. This hides real work. Be specific.
Quick recap
  • .gitignore lists patterns of files Git should not track.
  • Commit it so your whole team shares it.
  • Already tracked files need git rm --cached first.
  • Secrets in old history stay leaked until you rotate them.
