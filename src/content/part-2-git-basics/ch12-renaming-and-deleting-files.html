Renaming and deleting files

Git tracks file moves and deletions too, and the right commands keep the history clean.

12.1 Deleting a tracked file

$ git rm old-notes.txt
rm 'old-notes.txt'
$ git status
Changes to be committed:
	deleted:    old-notes.txt
$ git commit -m "Remove old notes"

git rm deletes the file from disk and stages the deletion in one step. If you delete a file in your file explorer instead, Git notices it as an unstaged deletion. Stage it with git add -A or git rm <file>.

12.2 Stop tracking but keep the file

$ git rm --cached config.local

This removes the file from Git's tracking but leaves it on disk. Pair it with .gitignore (Chapter 10).

12.3 Renaming and moving

$ git mv draft.txt final.txt
$ git status
Changes to be committed:
	renamed:    draft.txt -> final.txt

git mv is the same as renaming the file yourself and then running git add on both names. Git does not store renames explicitly. It detects them by comparing contents, so a rename plus tiny edits is still recognised.

12.4 Restoring a deleted file

Deleted something by mistake? It is still in history.

$ git restore old-notes.txt
$ git restore --source=HEAD~2 old-notes.txt

The second form brings the file back from two commits ago.

12.5 Common mistakes

  • Deleting with the file explorer and forgetting to stage. The deletion is not committed until you stage it.
  • Renaming and changing a file in one commit. If too much changes, Git may not recognise the rename. Rename first, commit, then edit.
Quick recap
  • git rm deletes and stages the deletion.
  • git rm --cached stops tracking but keeps the file.
  • git mv renames or moves a file and stages the change.
  • Deleted files can be brought back from history with git restore.
