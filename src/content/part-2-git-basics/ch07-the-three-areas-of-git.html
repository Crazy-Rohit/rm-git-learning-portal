The three areas of Git

Git moves your work through three areas, and understanding them explains almost every Git command.

Course

The stage 1 command block does this three times: edit a file (working directory), git add (staging area), git commit (repository). Paste the whole block so you get three commits. Stage 1 guide

7.1 The idea: a photo studio

Imagine a photo studio. The working directory is the stage where you arrange people and props. The staging area is the shelf where you place exactly the items you want in the next photo. The repository is the album where finished photos are stored forever. You can rearrange the stage as much as you like. Only what you place on the shelf gets photographed, and once a photo is in the album it stays there.

7.2 Why a staging area exists

Many beginners ask why Git does not just save everything you changed. The staging area lets you build clean commits. If you fixed a bug and also reformatted another file, you can stage and commit them separately. Each commit then tells one story, which makes history easy to read and easy to undo.

7.3 Adding files with git add

$ git add README.md
$ git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   README.md

The file is now staged. Useful variations:

CommandWhat it stages
git add file.txtOne file
git add file1.txt file2.txtSeveral named files
git add src/Everything inside a folder
git add *.pyAll Python files in the current folder
git add .Everything new or changed from here downward
git add -AEverything new, changed or deleted in the whole project
git add -pPick individual pieces of a file, one at a time

7.4 A file can be in two states at once

Edit a file after staging it and Git remembers both versions: the one you staged, and the newer one in your working directory.

$ echo "More text" >> README.md
$ git status
Changes to be committed:
	new file:   README.md

Changes not staged for commit:
	modified:   README.md

Only the staged version goes into the next commit. Run git add README.md again to include the newer edit.

7.5 Staging part of a file

git add -p shows each changed chunk (called a hunk) and asks what to do.

$ git add -p
@@ -1,2 +1,3 @@
 # Hello Git
+More text
Stage this hunk [y,n,q,a,d,s,e,?]? y
KeyMeaning
yStage this hunk
nDo not stage this hunk
sSplit into smaller hunks
qQuit

7.6 Common mistakes

  • Using git add . blindly. It can stage secrets, build files or large data. Always run git status before committing.
  • Forgetting to stage again after editing. The commit contains the staged version, not your latest edit.
  • Thinking git add saves your work. Staging is only a preparation step. Nothing is saved to history until you commit.
Quick recap
  • Working directory, staging area and repository are the three areas.
  • git add moves changes into the staging area; git commit moves them into the repository.
  • The staging area lets you build small, focused commits.
  • git add -p stages part of a file.
Check yourself

1. What does git add do?

Staging prepares a commit. The commit itself is a separate step.

2. You edit a file after staging it. Which version goes into the next commit?

Git commits what is staged. Stage again to include the newer edit.

Practice exercise
  • Create two files, a.txt and b.txt, and stage only a.txt. Check with git status.
  • Edit a.txt after staging it and run git status to see the file listed twice.
  • Practise git add -p on a file with two separate edits.
