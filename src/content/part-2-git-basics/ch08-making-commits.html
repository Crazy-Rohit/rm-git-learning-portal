Making commits

A commit is a permanent snapshot of your staged changes together with a message explaining why you made them.

8.1 Your first commit

$ git commit -m "Add README"
[main (root-commit) 3f2a9c1] Add README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md

Let us read this output. main is the branch, 3f2a9c1 is the start of the commit's unique ID (its hash), and the last lines say what changed.

8.2 What a commit contains

Every commit points to its parent, the commit before it. These links form the history chain that you saw in Chapter 1.

8.3 Commit command variations

CommandWhat it does
git commit -m "message"Commit with a one-line message
git commitOpen your editor to write a longer message
git commit -a -m "message"Stage all changes to tracked files, then commit
git commit --amendReplace the last commit with a new one
git commit --allow-empty -m "message"Create a commit with no file changes
Note

-a only picks up files Git already tracks. Brand new files still need git add.

8.4 Writing good commit messages

A good message explains why, not just what, and makes sense to a stranger a year from now.

Fix crash when the username is empty

The login form passed an empty string to validate(), which
raised an exception. Return a friendly error instead.
  • Write a short first line of about 50 characters, in the imperative mood: "Add", "Fix", "Remove".
  • Leave a blank line, then add details only if they help.
  • Describe one logical change per commit.
Weak messageBetter message
updateAdd password length check to signup
fixed stuffFix off-by-one error in pagination
final versionPrepare release 1.2.0

8.5 Fixing the last commit with --amend

You committed, then noticed a typo or a forgotten file. Amend rewrites the last commit.

$ git add forgotten.txt
$ git commit --amend -m "Add README and licence"
Caution

Never amend a commit that you have already pushed to a shared branch. Amending creates a different commit, and teammates who already have the old one will run into conflicts.

8.6 Common mistakes

  • Committing with no message or a vague one. Future you will not remember what "stuff" meant.
  • Huge commits that mix unrelated changes. Use git add -p to split them.
  • Committing secrets such as passwords or API keys. Removing them later is painful. Part 5 covers prevention.
Quick recap
  • A commit is a snapshot plus author, date, message and a link to its parent.
  • git commit -m "message" saves what is staged.
  • Write short, imperative messages that explain why.
  • --amend fixes the last commit, but only before you share it.

Practice exercise
  • Make your first commit with a clear message.
  • Change a file, stage it, commit it, then fix the message with git commit --amend.
  • Write one commit whose message explains why, not only what.
