Glossary

Plain-language definitions of the terms used in this handbook.

44.1 Terms

TermMeaning
ActionA reusable step used in a GitHub Actions workflow
AmendTo replace the most recent commit with a new one
ArtifactA file saved from a workflow run, such as a report
BisectBinary search through history to find the commit that introduced a bug
BlameA view showing who last changed each line of a file
BranchA movable pointer to a commit; a line of work
CheckoutTo switch branches or restore files (older command, now partly switch and restore)
Cherry-pickCopy a single commit onto another branch
CI/CDContinuous integration and delivery: automatic building, testing and deploying
CloneA full copy of a repository, including history
CommitA saved snapshot with message, author and parent
ConflictA merge problem where both sides changed the same lines
DependabotGitHub's tool for dependency alerts and update pull requests
Detached HEADHEAD pointing straight at a commit instead of a branch
DiffA comparison showing added and removed lines
Fast-forwardA merge that only moves a pointer, with no new commit
FetchDownload remote commits without changing your files
ForkYour own GitHub copy of someone else's repository
HEADPointer to your current branch or commit
HookA script Git runs at a set moment, such as before a commit
IndexAnother name for the staging area
IssueA tracked bug, task or request on GitHub
LFSLarge File Storage, for big binary files
MainThe conventional name of the default branch
MergeCombine the work of two branches
MonorepoOne repository holding many projects
OriginThe default name of the main remote
PullFetch and merge in one step
Pull requestA proposal to merge a branch, with review and checks
PushUpload commits to a remote
RebaseReplay commits on top of another base
ReflogLocal diary of where HEAD and branches have pointed
RemoteA repository copy hosted elsewhere
RepositoryA project and its complete history
RevertCreate a commit that cancels an earlier one
SquashCombine several commits into one
Staging areaWhere changes wait to be included in the next commit
StashA shelf for unfinished changes
SubmoduleA repository nested inside another at a fixed commit
TagA permanent name for a commit
UpstreamThe original repository you forked, or the remote branch a local branch follows
Working directoryThe files you see and edit

You have reached the end of the handbook. The best next step is practice. Build a small project, open a pull request, review someone else's, and contribute to an open-source project you like.
