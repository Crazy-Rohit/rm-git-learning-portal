Interview questions

These questions come up again and again in developer interviews, with short answers you can explain in your own words.

43.1 Basics

What is the difference between Git and GitHub?

Git is a free, distributed version control tool that runs on your computer. GitHub is an online service that hosts Git repositories and adds collaboration features such as pull requests, issues and Actions.

What is a commit?

A commit is a snapshot of the staged project files with an author, date, message and a link to its parent commit. It is identified by a hash.

Explain the three areas in Git.

The working directory holds the files you edit, the staging area holds the changes chosen for the next commit, and the repository stores the committed history in the .git folder.

What is the difference between git fetch and git pull?

Fetch downloads new commits and updates remote-tracking branches without changing your files. Pull runs fetch and then merges (or rebases) the result into your current branch.

What does git clone do compared with git fork?

Clone copies a repository, with its history, to your computer. A fork is a copy of a repository in your own GitHub account, used to propose changes to projects you do not own.

What is HEAD?

HEAD is a pointer to your current position, usually the branch you are on, which in turn points to its latest commit.

43.2 Branching and merging

What is a branch, and why are branches cheap in Git?

A branch is a movable pointer to a commit. Creating one only writes a tiny file with a hash, so it is instant and uses almost no space.

What is the difference between merge and rebase?

Merge joins two histories with a merge commit and keeps the real branching shape. Rebase replays your commits on top of another branch, creating new commits and a linear history.

When should you not rebase?

Never rebase commits that are already shared with others, because it rewrites history and breaks their copies.

What is a fast-forward merge?

When the target branch has no new commits, Git just moves its pointer forward to the other branch's tip, without creating a merge commit.

How do you resolve a merge conflict?

Open the conflicted files, choose or combine the correct content, remove the conflict markers, git add the files, then commit or run the continue command.

What does git cherry-pick do?

It copies one or more specific commits onto the current branch, creating new commits with new hashes.

What is git stash used for?

It temporarily shelves uncommitted changes so you can switch tasks with a clean working directory, and you bring them back later with git stash pop.

43.3 Undoing and recovery

What is the difference between git reset and git revert?

Reset moves the branch pointer back and rewrites history, so it is for local commits. Revert adds a new commit that cancels an earlier one, so it is safe for shared history.

Explain reset --soft, --mixed and --hard.

All three move the branch. Soft keeps changes staged, mixed (the default) unstages them but keeps the files, and hard also discards the file changes.

How would you recover a commit you lost after a hard reset?

Run git reflog to find the commit hash, then create a branch at that hash or reset to it.

How do you undo the last commit but keep the work?

git reset --soft HEAD~1 if it is not pushed. If it is pushed, use git revert instead.

You committed a password. What do you do?

Revoke and replace the password immediately. Then remove it from history with a tool such as git filter-repo, force-push, and ask collaborators to re-clone.

43.4 GitHub and teamwork

What is a pull request, and why use one?

A pull request proposes merging one branch into another and hosts review, discussion and automated checks before the code reaches the main branch.

What are the merge options on a pull request?

Merge commit keeps all commits plus a merge commit, squash and merge combines the branch into one commit, and rebase and merge replays the commits without a merge commit.

What is GitHub Actions?

A built-in automation service that runs workflows, defined in YAML files, in response to events such as pushes and pull requests, commonly for continuous integration and deployment.

What is branch protection?

Repository rules that stop risky actions on important branches, such as pushing directly, force-pushing or merging without approvals and passing checks.

Describe a good Git workflow for a team.

Branch from main for each change, commit small and clearly, open a pull request, get a review and passing checks, merge, delete the branch. Protect main and keep branches short-lived.

How do SSH keys work with GitHub?

You keep a private key on your computer and give GitHub the public key. GitHub verifies that you hold the private key without it ever being sent.

What is .gitignore?

A file listing patterns of files Git should not track, such as secrets, dependencies and build output.

What are tags used for?

Tags permanently name a commit, usually to mark a release such as v1.0.0.

Quick recap
  • Be ready to explain the three areas, merge versus rebase and reset versus revert.
  • Describe a team workflow from branch to pull request to merge.
  • Know how to recover lost work with the reflog.
