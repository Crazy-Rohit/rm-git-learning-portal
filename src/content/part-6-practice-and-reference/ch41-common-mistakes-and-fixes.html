Common mistakes and fixes

Everyone makes the same Git mistakes, and almost all of them have a short, safe fix.

41.1 I committed on the wrong branch

You meant to work on a feature branch but committed on main, and have not pushed yet.

$ git branch feature-x
$ git reset --hard origin/main
$ git switch feature-x

The first line keeps your commits on a new branch, the second moves main back to match the remote, and the third takes you to your work.

41.2 I want to undo my last commit but keep the changes

$ git reset --soft HEAD~1

41.3 I forgot a file in the last commit

$ git add forgotten.txt
$ git commit --amend --no-edit

41.4 I need to undo a merge

$ git merge --abort
$ git reset --hard ORIG_HEAD
$ git revert -m 1 <merge-hash>

Use the first when the merge is still in progress, the second right after a merge you have not pushed, and the third for a merge that is already pushed.

41.5 I committed a file that should be ignored

$ git rm --cached secrets.txt
$ echo "secrets.txt" >> .gitignore
$ git commit -am "Stop tracking secrets.txt"

If it held a real secret, follow Chapter 38.

41.6 Error messages and what they mean

MessageMeaning and fix
fatal: not a git repositoryYou are in the wrong folder. cd into the project
error: failed to push some refsThe remote has new work. Run git pull, then push
Permission denied (publickey)GitHub does not accept your SSH key. Check ssh -T git@github.com and ssh-add -l
Authentication failedUse a personal access token or SSH; passwords are not accepted
refusing to merge unrelated historiesTwo repositories started separately. Use --allow-unrelated-histories once, knowingly
src refspec main does not match anyThere is no commit yet, or your branch has another name. Commit, then git branch -M main
Your local changes would be overwrittenCommit or git stash before switching or pulling
CONFLICT (content)Fix the markers, git add, then commit or --continue (Chapter 16)
detached HEADYou are on a commit, not a branch. git switch -c name keeps your work
warning: LF will be replaced by CRLFLine-ending difference. Set core.autocrlf (Chapter 5)
remote: error: File is 120 MBGitHub blocks files over 100 MB. Use Git LFS (Chapter 37)

41.7 I think I lost my work

Do not panic and do not run more commands blindly. Run git reflog, find the commit, and create a branch at it (Chapter 35). Uncommitted edits are the only thing Git cannot return.

41.8 Safety habits

  • Run git status before and after every important command.
  • Commit often so there is something to go back to.
  • Create a backup branch before a risky operation: git branch backup.
  • Use --dry-run or -n where a command offers it.
  • Prefer --force-with-lease to --force.
Quick recap
  • Most mistakes can be fixed with reset, revert, amend or the reflog.
  • Read error messages: they usually name the fix.
  • git status and a backup branch make risky work safe.
  • Uncommitted work cannot be recovered, so commit often.
