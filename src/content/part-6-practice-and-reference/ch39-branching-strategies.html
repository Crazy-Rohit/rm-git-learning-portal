Branching strategies

A branching strategy is the team's agreement on how branches are named, used and merged, and the right one depends on how often you release.

39.1 Why you need one

Git lets you branch in any way you like, which is exactly the problem. Without an agreement, every developer does something different, and merging becomes painful. A strategy gives everyone the same map.

39.2 GitHub Flow

The simplest model, used by many web teams. main is always ready to deploy. All work happens on short-lived branches that are merged by pull request.

39.3 Git Flow

A heavier model for software with versions and scheduled releases, such as mobile apps and libraries. It has permanent branches (main and develop) and temporary ones (feature, release, hotfix).

BranchPurpose
mainReleased code only, tagged with versions
developIntegration of finished features
feature/*One feature each, branched from and merged back into develop
release/*Final fixes before a release
hotfix/*Urgent fixes branched from main

39.4 Trunk-based development

Everyone works on one shared branch, the trunk (main). Changes are tiny and merged at least daily, directly or through very short-lived branches. Unfinished features are hidden behind feature flags, switches that turn code on or off without a new deployment. It is the style used by many large teams that deploy continuously, and it relies on strong automated tests.

39.6 How to choose

  • Deploy several times a week? Start with GitHub Flow.
  • Ship numbered versions and support older ones? Consider Git Flow, or a simplified release-branch version of it.
  • Have excellent tests and an experienced team? Try trunk-based development.

39.7 Common mistakes

  • Choosing Git Flow because it looks professional. It adds overhead that small teams do not need.
  • Long-lived feature branches. The longer a branch lives, the worse the conflicts.
  • Having a strategy nobody wrote down. Put it in CONTRIBUTING.md.
Quick recap
  • A branching strategy is a shared agreement on how work flows.
  • GitHub Flow: short branches and always-deployable main.
  • Git Flow: develop, release and hotfix branches for versioned software.
  • Trunk-based: tiny, frequent merges and feature flags.
